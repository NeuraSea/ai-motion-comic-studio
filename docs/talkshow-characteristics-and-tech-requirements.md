# 脱口秀数字人：品类特点 → 技术需求映射

> 状态：调研结论（2026-08），作为 Phase 2/3 节点设计的产品输入
> 关联：[`modularization-and-canvas-dag-design.md`](./modularization-and-canvas-dag-design.md)（Phase 0/1 已实现基线）
> 范围：真人数字人（数字分身驱动真人口型）路线，非 TTS 配音路线；核心论点是**脱口秀的技术难度集中在时间控制（timing），而非画面**

---

## 0. 一句话结论

漫剧的技术重心是**视觉一致性**（角色三视图、分镜参考、跨镜连贯）；脱口秀数字人的技术重心是**时间控制**——气口、节奏、观众反应全都生活在时间轴上。画面几乎是免费的（单人、单机位、固定舞台），但时间维度错了 300ms 段子就垮了。**这决定了 Phase 2 的节点设计必须把"时间"作为一等公民。**

---

## 1. 调研：脱口秀的品类特点

### 1.1 节奏（Pacing / Timing）—— 段子的物理结构

单口喜剧（stand-up）的基本单位是 **setup → punchline**（铺垫 → 包袱）。包袱落地依赖精确的**喜剧停顿**：

- 铺垫末句收尾 → **停顿 0.5–1.5s**（"喜剧节拍"，让观众预期聚拢）→ 包袱抛出
- 包袱抛出 → **停顿等待笑声**（不能立刻接下一句，否则"踩笑声"）
- 错误示范：AI 生成的匀语速配音把所有停顿抹平，包袱像"念稿"，这是数字人脱口秀最容易翻车的地方

**关键技术事实**：停顿不是"没有声音"，而是**带表情和眼神的表演间隙**。观众在停顿里读演员的脸。

### 1.2 气口（Breath / Cadence）

- 真人说段子的呼吸点、换气声、语流中的微小卡顿（"其实……我觉得吧"）构成**人味（humanity）**
- 数字人若输出匀速、无换气、无口水音的完美语音，会立刻显得"假"
- 气口位置与喜剧停顿**不完全重合**：气口是生理的，停顿是表演的，两者叠加才是真实语流

### 1.3 观众反应（Laughter / Crowd Work）

- 笑声是脱口秀的**第二音轨**：包袱后的笑声时长（0.5–3s 不等）是节奏的一部分
- 成熟的演员会**等笑声**（ride the laugh），笑声起时保持微笑不接话，笑声将落才接下一句
- **现挂 / crowd work**：与观众即兴互动，是"真实感"的最强信号，也是数字人最难伪造的部分（需要分支对话能力）
- 视频版式上，笑声段落常配**观众反应镜头**（laughing cutaway）或演员的反应特写

### 1.4 镜头语言（Camera Grammar）

- 单口脱口秀是**极度克制的镜头语言**：主体是中景（MCU，胸上）或中近景，偶有特写（CU）强调包袱
- **推近（push-in）**：包袱即将抛出时缓慢推近，制造紧张感——这是漫剧 `uniformScaleMotion` 已能表达的
- **切观众（cut to audience）**：笑声节点的反应镜头
- **手持微晃 / 呼吸感**：完全静止的数字人画面会"死"，需要极轻微的相机呼吸感
- 没有漫剧那种跨场景、多角色、多机位调度——**画面复杂度低，时间复杂度高**

### 1.5 字幕与信息传达

- 脱口秀字幕**逐句居中、字号大、停留短**，包袱词常**加粗/变色/放大**（"梗"的视觉强调）
- 很多厂牌用**花字 / 弹幕**增强网感
- 漫剧的同源字幕（词级 sidecar）是基础，但脱口秀需要**逐词时间轴 + 强调标记**

### 1.6 内容形态与时长

- 单段表演（bit）：30s – 3min；合集：5–15min
- 远超漫剧单镜 4–15s 的约束 → **必须分段生成再拼接**（与 Phase 0/1 已实现的逐句/逐段思路一致，但段落边界应由**包袱结构**而非固定时长决定）

## 2. 映射到技术需求

把上面的品类特点翻成可工程化的需求，并标注**代码库现状**。

### 2.1 时间轴控制是核心（最重要）

| 需求 | 说明 | 现状 / 落点 |
| --- | --- | --- |
| **包袱结构驱动的分段** | 不按固定时长切，而按 setup/punchline 边界切分生成单元 | 新增：脚本输入需支持结构化标记（见 §3.1） |
| **喜剧停顿注入** | 在指定字符后插入可控时长停顿 | **可复用** `line-performance.ts` 的 `pausePlan`（`afterCharacter` + `durationSeconds`，已校验递增/越界） |
| **等笑声间隙** | 包袱后自动留出笑声窗口，下一句推迟 | 新增：timeline 上 punchline 段的尾帧延长 / 静帧延长 |
| **音频驱动的帧级对齐** | 语音实测时长 → 24fps 帧边界，不漂移 | **已具备** `shot-video-duration.ts` 的 `ShotVideoDurationDecision` |

### 2.2 真实感的"人味"注入

| 需求 | 说明 | 现状 / 落点 |
| --- | --- | --- |
| **气口 / 换气** | 保留或合成呼吸点、微小卡顿 | TTS 路线：`speechRate`/`emotion`/`context_texts`（豆包已有）；真人录音路线天然具备 → **优先真人录音或高质量克隆** |
| **情绪/表演指令** | 每段的语气（自嘲/得意/无奈） | **可复用** `EMOTION_CONTEXT`（豆包）+ MiniMax `emotion`；漫剧 `line-performance` 的逐句表演指令概念可直接平移 |
| **表情/眼神在停顿中的延续** | 停顿时数字人不能"定格死脸"，要有微表情 | 视频模型侧：首帧 + 提示词指定"停顿微笑/挑眉"；或长源片裁切保留表演余韵 |

### 2.3 观众反应作为第二音轨

| 需求 | 说明 | 现状 / 落点 |
| --- | --- | --- |
| **笑声素材库** | 授权笑声/掌声 SFX，按包袱强度分级 | **可复用** BGM/SFX 上传（`media-upload.ts` 的 `bgm`/`sfx` kind） |
| **笑声落点编排** | 在 timeline 上把笑声 clip 精确放到 punchline 后 | **可复用** `AudioRenderClip`（`audioRole: 'sfx'` + `startFrame` 精确帧定位） |
| **反应镜头** | 笑声段的观众画面或演员反应特写 | 新增节点类型：reaction cutaway（静态图/短视频片段插入） |
| **ducking** | 笑声起时压低人声残留/BGM | **已具备** `AudioDuckingWindow` + FFmpeg 确定性 ducking |

### 2.4 镜头与剪辑

| 需求 | 说明 | 现状 / 落点 |
| --- | --- | --- |
| **推近（push-in）** | 包袱前缓推 | **已具备** `uniformScaleMotion`（静态图中心缩放）；视频 clip 需扩展 |
| **切反应镜头** | 笑声节点切观众/特写 | 新增：reaction 段的 visual clip 插入（复用 `VideoRenderClip`/`StaticImageRenderClip`） |
| **相机呼吸感** | 极轻微手持晃动 | 新增（低优先级）：subtle motion，或接受静态但用推近/切换制造动感 |

### 2.5 字幕与花字

| 需求 | 说明 | 现状 / 落点 |
| --- | --- | --- |
| **逐词时间轴** | 包袱词精确对齐 | **已具备** MiniMax 词级 sidecar + `speech-subtitle.ts` 同源物化 |
| **包袱词强调** | 加粗/变色/放大 | 部分：`BurnedSubtitleTrack` 支持 ASS；需扩展 ASS override tags（`\b1`、`\c`、`\fs`）+ 逐词 cue |
| **花字/弹幕** | 网感增强 | 新增（低优先级）：花字 overlay 轨，复用标题/落版 ASS overlay 机制 |

### 2.6 分段与拼接

| 需求 | 说明 | 现状 / 落点 |
| --- | --- | --- |
| **结构感知分段** | 按包袱结构而非固定 15s 切 | 新增：分段边界来自结构化脚本，非均匀切 |
| **跨段口型/表演一致性** | 同一张脸在多段间连贯 | 复用参考图集（Phase 0/1 已实现）+ 首帧链（前段尾帧作后段首帧，可选） |
| **总长扩展** | 30s–3min，突破单镜 15s | **已具备**分段 + FFmpeg concat（Phase 0/1 已验证） |

## 3. 对 Phase 2 节点/管道设计的具体影响

### 3.1 输入侧：结构化脚本 Schema（最关键的新增）

漫剧输入是自由文本原著；脱口秀输入应是**带表演标记的结构化脚本**。建议：

```jsonc
{
  "performer": { "photoAssetId": "...", "voiceId": "...", "style": "自嘲/犀利" },
  "beats": [
    {
      "type": "setup",
      "text": "其实我觉得做脱口秀最难的，不是写段子。",
      "delivery": { "emotion": "calm", "speed": 1.0 }
    },
    {
      "type": "pause",
      "kind": "comedic_beat",
      "durationSeconds": 0.8
    },
    {
      "type": "punchline",
      "text": "是你要在台上，假装自己过得很好。",
      "delivery": { "emotion": "deadpan", "emphasis": ["假装"] },
      "camera": { "pushIn": true },
      "reaction": { "laughter": "medium", "waitForLaugh": true }
    }
  ]
}
```

新增 `beat` 类型（setup / punchline / pause / crowd_work / callback），它是 DAG 中"分段 + 编排"的事实源。**这是与漫剧最根本的输入差异。**

### 3.2 新增/调整的节点类型（对设计文档 §4.2 `@manju/nodes-*` 的扩充）

| 节点 | 职责 | 复用 / 新增 |
| --- | --- | --- |
| `talkshow.script.parse` | 结构化脚本 → 分段 + 表演/反应清单 | **新增**（确定性，免费） |
| `talkshow.speech.perform` | 逐 beat 合成/对齐语音，注入停顿/情感 | 复用 speech，**扩** `pausePlan` + `emotion` |
| `talkshow.timing.beats` | 包袱结构 → 帧级时间轴（含等笑声窗口） | 复用 `shot-video-duration`，**扩** reaction 窗口 |
| `video.seedance` | 逐 beat 首帧视频（推近/表情提示词） | 复用，**扩** 表演提示词模板 |
| `talkshow.reaction.mix` | 笑声/掌声 SFX 在包袱后落点 + ducking | 复用 audio ducking，**新增** reaction 编排 |
| `talkshow.subtitle.punchline` | 逐词字幕 + 包袱词强调（ASS） | 复用词级物化，**扩** ASS override |
| `export.ffmpeg` / `qc` | 拼接 + 七项 QC | 复用（不变） |

### 3.3 不建议为脱口秀引入的

- **完整 crowd work 分支对话**：即兴互动需要实时对话状态机 + 口型对齐，远超 Phase 2 范围。Demo 阶段用"预录现挂"（演员提供的固定互动段）即可。
- **全自动笑点检测**：哪句是包袱应由**创作者在脚本里标注**（可控、可审计），而非模型猜测——符合"质量可控"的产品承诺。

---

## 4. 一句话给 Phase 2 的优先级

1. **P0**：结构化脚本 schema（包袱/停顿/反应标记）+ 包袱驱动分段 —— 这是品类灵魂
2. **P0**：喜剧停顿注入 + 等笑声窗口（帧级时间轴）—— 复用 `pausePlan` + 时长决策
3. **P1**：笑声 SFX 编排 + ducking + 反应镜头切换 —— 真实感的第二音轨
4. **P1**：逐词字幕 + 包袱词 ASS 强调 —— 复用词级 sidecar
5. **P2**：push-in 视频扩展、相机呼吸感、花字 —— 锦上添花
